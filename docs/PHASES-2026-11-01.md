# DOMUREVA — next build phases implemented directly in GitHub

Date: 1 November 2026. Development branch: `upgrade/domureva-trust-ux-20261031`; review PR: #3.

**No Lovable editor or Lovable credits were used.** Work is committed directly through the GitHub integration. The original Lovable-connected `main` branch remains unchanged until the user reviews an independently verified release.

## Phase 1 — case command centre (code built)

- `/api/cases/summary`: authorised case status, audited milestones, real evidence/quote/task counts and funding indication.
- `/api/cases/tasks` GET/POST/PATCH: list, create and complete saved tasks. Only authorised case managers create tasks; a verified assigned contractor/surveyor may complete their own task. Writes include audit events and reject stale task states.
- `/api/messages` GET/POST: private case-scoped message history and persisted messages with authenticated role checks.
- `CaseOperations` and `CaseFundingReview`: responsive task manager, blocking tasks, messages, stage history, real funding and evidence KPIs and links to authorised workflows.
- Case detail now presents stage-specific next steps and the normal workspace navigation; unknown stages do not quietly default to a fabricated funding stage.

## Phase 2 — geographically accountable Reva Fund (code built)

- Postcode lookup uses [Postcodes.io](https://postcodes.io/docs/postcode/lookup/) with a 5-second timeout, strict parsing and no street address, case identifier or user account data in the request.
- The postcode is resolved to a UK constituent country, outward postcode district and an available council GSS code.
- Reviewed schemes are assessed against explicit geography fields (`scope: "uk"`, `nations`, `outcodes`, `postcodes`, `local_authority_codes`), inclusive validity dates and source inspection timestamps.
- Missing geography, unsupported restrictions, stale sources, absent reviewed date, invalid postcode or external service downtime block an *automatic positive match* and create review-required entries.
- Existing positive matches that are no longer supported are invalidated, and progressing cases are not moved backwards.
- The case Funding tab shows reviewed scheme names, source links, review dates, source freshness and the outstanding review queue; authorised users can trigger an updated preliminary screen.
- The source inspection threshold (90 days) is an **internal data-quality gate**, not a legal rule. Funding eligibility/award still requires the administering authority.
- `DOMUREVA_POSTCODE_LOOKUP_DISABLED=true` is an optional server-side kill-switch. If the lookup is disabled or unavailable, geography is not assumed.

## Phase 3 — council portfolio privacy (code built)

- `/api/council/portfolio` uses **explicit `case_members` council_officer assignments**, not broad council organisation membership.
- Council route `/council/map` now displays actual assigned-case district coverage, stage filters and case links. Exact property coordinates and owner identities are removed from this view.
- This is an interactive *district-distribution view*, **not** a street-level map or a national empty-home census. An actual geospatial map requires a securely licensed tile provider and new acceptance testing.

## Phase 4 — operator dashboards and release governance (code built)

- `/api/admin/operations` and `/api/admin/security` demand `DOMUREVA_PLATFORM_ADMIN_USER_IDS` via the existing platform-gated server auth.
- Admin dashboards now read case-safe operational records from those APIs, not direct browser reads of global risk, webhook and audit tables.
- The integration dashboard no longer has the misleading, nonfunctional "sync now" control that omitted required case IDs; pending jobs are shown as pending.
- Release acceptance UI no longer allows user checkbox selections to masquerade as independent CI, RLS, accessibility or backup verification. The server still fails closed.
